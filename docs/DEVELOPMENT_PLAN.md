# iOS 完善计划

更新日期：2026-11-09。

## 项目定位与参考基线

目标是将现有 iOS 项目完善为可日常使用的原生下载工具。Android 用作功能、任务行为和异常处理的参考，Python XHS-Downloader 用作解析规则与媒体资源处理的上游依据。

本次检查的本地版本：

| 项目 | 基线 | 用途 |
| --- | --- | --- |
| iOS | `da73c4e`，`main` | 实际开发和交付项目 |
| Android | `bc810a6`，`main` | 参考已实现的结构化解析、持久任务、选择下载、网页会话、归档等行为 |
| XHS-Downloader | `pyproject.toml` 标记为 2.8；用户下载的源码快照，无 `.git` | 核对图片地址生成、视频候选、实况组件、笔记信息和下载规则；不能据此推定具体上游 commit |

默认采用本机运行的 Swift 实现：把上游规则适配到 iOS，结合 Android 已处理的实际案例，使用 URLSession、WebKit、Photos 和 AVFoundation。上游 FastAPI `/xhs/detail` 接口可作为将来的服务接入选项，首轮不增加服务部署依赖。

最低版本统一为 **iOS 26.0**，面向自签日常使用，主应用与扩展保持一致版本。Android 提供行为参考，界面按 iOS 原生习惯设计。

## 已确认的产品方案

- 下载、媒体库、设置三个原生标签页；iPad 自适应侧栏。柔和彩色背景配系统 Liquid Glass，下载珊瑚色、媒体库青色、设置紫色。媒体画面保持原色；支持深浅色、动态字体、VoiceOver、减少透明度/动态效果，操作区域至少 44pt。
- 下载页输入/粘贴入口、活动任务优先、搜索与筛选；任务可暂停/恢复/取消/重试。默认直接下载，全局“下载前选择”改为缩略图选择，Live Photo 一张逻辑卡片。
- 剪贴板自动下载默认开启，用户可以关闭；仅启动/回前台/前台剪贴板变化时读取，同一次变化只处理一次，跳过应用自己的复制。先消费分享，再检查剪贴板，合并相同活动任务，允许主动再次下载已完成笔记。
- 分享扩展优先完整文字并补充 URL；App Group 逐条原子请求文件，UUID 幂等，主应用持久入队后确认。`xhsdn://import?request=UUID` 仅携带请求 ID。自签跳转实验隔离；先保存、再尝试跳转，失败保留请求并明确提示手动打开，不能当作跳转成功。
- Photos 为原件主存储，专用“小红书下载器”相册，申请 readWrite，支持有限访问。保存原件与加入相册在一次事务内，保存成功才记成功并清理传输文件。保存相册标识，删除后下次保存重建。媒体库观察 Photos 变化，处理权限/删除/iCloud；区分移除记录、移出相册、删除照片。
- 媒体库手机三列、iPad 自适应，支持搜索/类型筛选/多选；全屏黑底翻页，图片缩放、原生 Live Photo 长按与静音、AVKit 视频播放/PiP，离开停止播放。
- HDR 原件优先，不用 SDR 转码替代原件。图像保留容器、gain map、ICC/CICP，视频保留 HLG/PQ/HDR10/支持的 Dolby Vision 元数据。缩略图约束动态范围，全屏允许高动态范围；P3/HEVC/10bit 不能单独证明 HDR，不虚标当前显示效果。
- Live Photo 由解析的显式图片/视频配对产生，使用 ImageIO 元数据无损复制和 AVFoundation 直通封装，写入匹配内容标识及 still-image-time，Photos `.photo` + `.pairedVideo` 一资产保存。支持合成/分开/仅静态；无法无损处理时保留组件，报告降级，不能用安卓的 SDR JPEG 路径冒充 HDR 实况。
- Swift 原生底层；SwiftData 与数据访问 actor，旧 JSON 迁移保留备份、ID、时间、文件名、Photos 引用和设置，不在迁移时重新下载。分享扩展只写收件箱。
- 结构化 ResolvedNote/ResolvedMedia，一次解析标题正文作者和有序媒体，区分 UID/redId，按目标笔记匹配，多视频地址为候选，身份不依赖签名 URL。统一 .com/.cn/RedNote/裸链接/标点输入。
- 默认同时传输一个笔记、笔记内四个资源；等待选择不阻塞其他任务。后台 URLSession、字节进度/速度/检查点、HTTP/格式/长度/Range 校验、候选回退、地址过期重新解析，重试只处理失败资源，取消退出后再重试。预览缓存上限 512MiB，不清理活动/未保存原件。
- 后续接入持久网页登录、Keychain Cookie、已加载评论图、可选封面、媒体策略、redId/日期命名、作者备注、TXT/Markdown/Files 导出、JSON/CSV 记录导出与版本信息。相册一个专辑，文件导出可按作者/笔记分层。

## 本轮实施顺序

1. 三标签页与彩色玻璃、持久分享交接/自签跳转、剪贴板、专用相册及原生媒体查看；尽早验证真机分享冷/热启动。

| 能力 | iOS 当前实现 | 改进目标 |
| --- | --- | --- |
| 解析 | `XHSDownloader.swift` 内同时承担链接、页面、媒体、命名与传输；遍历 `noteDetailMap`，也会读取 feed | 按目标笔记 ID 匹配；一次解析得到正文、作者与有序媒体 |
| 链接 | `XHSURLDetector` 与下载器各有一套链接提取逻辑；未覆盖 RedNote | 统一入口，覆盖分享文本、多链接、短链接与 RedNote，并保留必要查询参数 |
| 视频 | 原始地址和流地址被展开为独立媒体，只读取 h264 流；无候选回退策略 | 一个逻辑视频保留多个编码、画质与备用地址，下载时选择和回退 |

| 任务 | 有 JSON 持久记录；每次提交立即启动；取消与中断均变成失败 | 有限并发、清晰状态、暂停/恢复、独立资源结果与中断恢复 |
| 重试与重复提交 | 一小时内相同 URL 被直接拒绝；重试重新遍历全部媒体，已有成功记录仍保留 | 重试只处理未成功资源；主动再次提交和智能跳过分开处理 |
| 网络 | 临时 URLSession，未接后台事件；媒体下载未校验 HTTP 状态，扩展名依赖 MIME/URL | 后台文件传输、字节进度、响应与实际格式校验、可恢复下载 |
| 实况 | 有开关、类型标记和 `saveLivePhoto` 方法，但下载路径始终调用 `saveMedia` | 保留图像与动态组件配对，生成 Apple Live Photo 并作为一个资源入库 |
| 网页 | 临时 WKWebView 仅获取 canonical URL；没有读取页面笔记数据，未与下载器共享会话 | 持久网页会话、页面数据提取，复用同一结构化笔记解析入口 |
| 归档与历史 | 有基础命名、任务筛选、相册引用和预览 | 文件导出、笔记文案归档、搜索与设置分组，区分移除记录和删除相册媒体 |

## 初始阶段拆分（历史参考）

### 阶段 0：建立开发基线

- [x] 阅读三份本地项目的核心实现和 Android 同步记录。
- [x] 完成主应用及分享扩展的无签名模拟器构建。
- [x] 尝试现有单元测试和首页 UI 测试，并记录模拟器启动阻塞；运行结果待验证。
- 已发现扩展 `CFBundleVersion=3`、主应用 `CFBundleVersion=4` 的构建警告；发布准备时统一。
- 测试代码存在 MainActor 隔离警告，当前 Swift 5 模式下可编译；调整核心逻辑所在 actor 时一并处理。

### 阶段 1：解析基础与真正的选择下载

1. 统一分享链接提取与短链接解析，按目标 ID 取得笔记，避免把推荐内容作为下载结果。
2. 引入结构化笔记与有序媒体模型：标题、正文、作者 UID/公开小红书号、时间、标签、图片、视频、实况配对、封面以及候选地址。
3. 让正文和媒体共用一次笔记解析；视频的不同地址作为同一资源的候选，保留各图与实况的原始顺序。
4. 选择界面改为远端缩略图预览，提交后只下载选中项；直接下载沿用同一解析结果。

验收：用本地固定样例覆盖多笔记页面的目标匹配、缺失目标、短链接、RedNote、正文换行、多编码视频与实况配对；选择前不请求完整媒体，提交只下载所选资源。

### 阶段 2：可靠传输与任务恢复

1. 分开解析、等待选择、传输和保存状态；增加暂停、取消、部分完成等明确结果。
2. 保存每个任务提交时的设置快照、稳定媒体身份、资源结果和下载检查点；为现有 JSON 记录提供兼容读取/迁移。
3. 用后台 URLSession 承载文件下载并接入完成事件，显示字节进度与速度；按任务和资源限制并发。
4. 校验 HTTP 状态、内容类型及实际文件格式；依次尝试候选地址。续传失败时允许重新请求，过期地址重新解析。
5. 重试保留已保存资源，避免重复写入相册；取消后旧任务不能继续覆盖新一轮重试状态。
6. 主动重复提交可建立新任务；智能跳过作为单独选项，启用时核对成功记录及资源是否仍可访问。

验收：本地 HTTP 测试覆盖 200/206/416、Range 不受支持、HTML 错误响应、断网、候选失败和取消；设备检查切后台、重开应用、部分成功后重试以及多个待选任务。升级前后的记录都可读。

后台能力按 [Apple 后台下载机制](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background) 实现；用户从多任务界面强制退出会取消后台传输，重新打开后提供恢复入口，见 [background(withIdentifier:)](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background(withidentifier:))。

### 阶段 3：原生实况照片与网页提取

1. 使用阶段 1 的明确配对，写入图像/视频匹配标识和必要时间元数据，通过 Photos 的 photo/pairedVideo 资源保存。
2. 提供实况、组件分别保存、仅静态三种行为；配对合成失败时保留可用组件，并报告实际结果。
3. 内置浏览器持久保存网页会话，提取当前笔记数据；参考 Android `xhs_extractor.js`，适配 WKWebView 调用方式。
4. 页面提取结果接入同一个笔记模型，复用选择、传输和保存链路；手动会话信息存入 Keychain。
5. 分享扩展继续通过 App Group 交接任务，检查重复交接、中断和入队失败的处理。

验收：iPhone 系统相册可识别、播放 Live Photo；多张实况不会错配；组件失败可重试。网页登录重开后仍可使用，页面提取取得的是当前笔记，分享扩展只入队一次。相册识别和账号流程需要真实设备验收。

### 阶段 4：日常使用体验与安装交付

- 保持 SwiftUI 与系统交互习惯，完善任务卡片、媒体选择、详情预览和 iPad 布局。
- 设置按媒体与格式、归档与记录、网络与会话分组，沿用现有本地化机制。
- 支持图片格式与视频策略、视频封面、TXT/Markdown 笔记导出、系统 Files 导出及历史搜索；作者归档与记录导出按使用价值接续。
- 区分相册保存和文件归档，保留原文件格式；目标格式不可用时说明实际保存结果。
- 覆盖图片、视频、实况、选择下载、权限拒绝、分享入口、升级迁移和后台恢复，完成版本号、签名与真机安装说明。

验收：从复制/分享链接到选择、下载、系统相册或 Files 查看形成完整操作链路；旧记录与已保存媒体可继续使用；安装包经过真机验证。
