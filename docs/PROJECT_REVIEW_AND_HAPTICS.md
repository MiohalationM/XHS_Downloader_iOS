## 触感原则与实现

统一入口为 `AppFeedback.play(_:)`。反馈描述操作含义，UIKit 生成器负责具体波形，避免 SwiftUI `sensoryFeedback` 与 UIKit 两套开关混用。生成器复用；选择后重新准备，返回和缩放手势开始时预热边界反馈。

- 默认开启，设置页可关闭。关闭立即作用于所有应用主动触感；系统原生控件的反馈由 iOS 控制。
- 主应用仅在前台播放，不缓存后台事件、不在回到前台时补播。分享扩展通过 App Group 读取同一偏好，只在可见时反馈提交和失败。
- 以实际改变为触发条件。重新点当前筛选、无效暂停、加载默认值、恢复设置和关闭错误提示不产生反馈。
- 轻反馈最小间隔 60ms；结果反馈后 350ms 内抑制同级或更轻反馈。任务结果之间至少间隔 1.5 秒，严重程度上升时可立即提示。
- 错误优先于警告，警告优先于成功，结果优先于轻触。批量暂停/继续/重试每次操作仅发一次确认，任务进度和每个媒体文件完成不震动。
- 不以连续振动模拟动画，不为每帧滚动、双指缩放过程、普通文字输入或下载字节变化增加反馈。

| 场景 | 反馈语义 | 强度与触发点 |
| --- | --- | --- |
| 主标签、笔记范围、媒体筛选、排序 | selection | 系统选择轻点，实际切换时 |
| 单项选择、全选/取消全选、合集成员 | selection | 一次逻辑选择一次；批量不逐项触发 |
| 设置开关、菜单选项、步进器 | selection | 仅用户写入 binding 时；关闭触感开关自身也静默 |
| 请求间隔、网页缩放滑块 | selection | 手指松开时一次 |
| 打开笔记、全屏、浏览器、输入页、分享、搜索 | navigation | soft impact，0.65 |
| 喜欢/收藏、放大、开始 Live Photo 播放 | activation | medium impact，0.65 |
| 取消喜欢/收藏、还原缩放、暂停/取消选择 | deactivation | soft impact，0.65 |
| 加入下载、确认选择、重试/继续 | confirmation | light impact，0.8；成功受理时 |
| 复制文案或链接 | copy | light impact，0.8；剪贴板写入后 |
| 图片翻页、Live Photo 静音切换 | selection | 页面/静音状态改变时 |
| 下拉或边缘返回越过距离阈值 | boundary | rigid impact，0.45；每次持有手势最多一次 |
| 未过距离阈值但快速甩动完成返回 | navigation | 松手确认完成时一次；已给阈值反馈则不重复 |
| 返回取消/回弹 | 无新增触感 | 不播放成功或错误 |
| 双指缩放抵达最小/最大边界 | boundary | 松手到达边界且起始不在该边界时一次 |
| 新建合集、实际删除完成、导入成功 | success | 系统成功反馈；失败或取消不得提前播放 |
| 下载完全成功 | taskResult completed | 系统成功反馈，批量限频 |
| 部分完成、实况降级未满足要求、带附属文件错误的完成 | taskResult partial | 系统警告反馈，仍可区分完全失败 |
| 删除确认、导出不完整 | warning | 系统警告反馈；确认弹出与执行完成分开 |
| 解析/保存/分享准备失败、浏览器错误 | error | 系统错误反馈；同一波失败不叠加 |
| 自动剪贴板、分享扩展导入 | confirmation | 只在已受理/已持久写入时；识别和读取过程静默 |

设置中的“体验触感反馈”提供五种语义的手动预览。它只演示反馈，不执行删除、下载或改动媒体。

## 动画与用户流程评估

卡片到详情、详情到全屏维持两级关系；静帧准备完成后再开启转场，有助于避免放大缩略图造成的模糊。返回期间锁定嵌套滚动，取消后恢复位置，仍保留回弹途中接住手势的能力。触感落在阈值或提交点，和这些动画阶段对应。

普通模式保留现有约 0.48 秒的弹簧及返回曲线。本轮不修改整体视觉风格。减少动态效果模式改为淡化；用户直接拖动时保留必要的触点关系，避免额外缩放。屏幕圆角和底栏交接继续使用现有实现。

下载前选择、直接下载、只保存笔记应由入口的明确选择决定。排队、等待选择、部分完成分别表达机器执行、需要用户操作和结果不完整；触感采用相同区分，不把“按下按钮”“完成保存”和“警告”都处理成同一种震动。

## 已明确的边界

备份恢复继续使用两个独立 store，采用可重试的分阶段恢复，不能宣称跨 store、跨进程的全有或全无事务。笔记已保存而任务或最终刷新失败时，界面明确提示部分恢复；偏好设置不提前应用。重复导入按身份合并，用户可继续恢复。

Photos 和 Files 的删除也没有跨系统原子回滚。系统照片确认在文件删除前完成；后续失败会保留未删除项并整理已删除项的引用。文件实况的一部分已删除而另一部分失败时，记录保留供重试，无法自动还原已被文档提供器删除的组件。

归档的本地授权持久化、目录迁移和路径边界已有模拟器回归。真实 iCloud 下载、第三方文档提供器的权限生命周期与锁屏后的访问仍需要对应设备和账号验收。测试通过不等于整项目不存在其他缺陷。

## 2026-11-14：全局右滑返回与等待落盘的触感（build 30）

用户明确要求笔记二级页在顶部、正文、图片和底部均可从左往右滑返回，本次解除之前 32pt 左缘限制。本段替代前文左缘返回的交互规则。右滑返回由整个详情容器识别，左滑仍交给媒体分页；纵向正文滚动、放大图片的平移、原有跟手曲线及短滑取消逻辑保持原有判定。

触感代码检查发现：任务状态改变时先检查前台/开关，但等待持久化完成后才播放，等待期间离开再回到前台、关闭再开启触感，旧结果仍可能播放。现在在场景阶段或触感开关变化时使待播放结果失效；保存后同时核对任务仍存在且状态未变。被丢弃的旧结果不会消耗新的反馈限频。反馈仍以成功持久化为前提。

有效验证：

- `.build/ios-dev/Test-20261114-125356.xcresult`：`FeedbackTests` 与 `NoteLibraryTests`，25 项通过。新增过期反馈抑制用例，保留方向、阈值每次持有只提示一次、取消无成功反馈、关闭/后台门控和结果限频检查。
- `.build/ios-dev/Test-20261114-125842.xcresult`：2 项 UI 测试通过。新用例验证顶部、图片第二页、滚动后的正文和底部操作栏右滑返回，正文短滑取消保持阅读位置；既有全屏用例验证缩放、缩至最小、翻页、下拉取消、回到所选图片和再次进入。

## 2026-11-14：继续检查回弹接续和滑块触感（build 31）
